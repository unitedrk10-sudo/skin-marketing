한국어 후기 릴스를 인스타그램 **리믹스 기능으로** 가져와 영어 번역을 붙인다. 내려받아 다시 올리지 않는다.

**결정 (2026-11-05)**
- **계정:** Skinbound
- **콘셉트:** "K-뷰티는 한국 사람들이 제일 잘 안다 — 그 이야기를 영어로 전해 준다." 원본은 한국어 콘텐츠다.
- **원본:** 유명 계정 위주로 찾는다. 협찬 표시가 있는 영상은 뺀다. 의사·병원 운영 계정도 뺀다 (그 자체가 병원 광고).
- **첫 주제:** 블로그에 이미 쓴 시술 하나를 고른다 (후보: 리쥬란, `#리쥬란` `#리쥬란힐러` `#리쥬란후기`).
- **구성 (2026-11-09 운영자 결정):** 다른 사람 릴스 리믹스 + **원문 그대로의 영어 번역** + 끝에 관련 블로그 글 링크 안내 한 줄 (예: "Our take on Rejuran → link in bio"). 우리 주장을 새로 쓰지 않으므로 블로그 사실 대조는 하지 않는다. 남는 기준은 셋: ① 어떤 영상을 퍼뜨릴지 선별(병원·협찬·DM 유도·주사·전후 비교 제외) ② 번역은 원문 그대로, 효과를 더하지 않음 ③ 캡션에 "Personal experience — results vary" 와 AI 번역 표시 한 줄. 원문 자체가 과장("한 번에 10년 젊어짐")이면 번역해도 퍼뜨리는 것이라 그 영상은 고르지 않는다.

- **홈페이지 연결 (2026-11-10 운영자 결정 — 릴스의 목적은 홈페이지 유입, 매출은 홈페이지 쪽):**
  - 프로필 첫 번째 링크 = 도착 페이지 `/ig/` 의 추적 링크 `https://go.skinboundkorea.com/a9rv99?s=ig` (라벨 "Instagram profile"). 프로필 링크는 최대 5개지만 첫 번째만 바로 보인다.
  - `/ig/` = 릴스에서 다룬 시술별 글 + 여행 일정 글 (`config/reels.yaml` 주제별 `posts`·`landing`, `pipeline/ig_page.py`). 검색 제외. 스폰서 글·코스 광고 카드가 붙은 글은 코드가 뺀다. 새 시술 릴스를 올리기 전에 그 시술 글을 `posts` 에 넣는다.
  - 스토리 링크 스티커: 팔로워 수 조건 없이 모든 계정이 쓸 수 있다 (2021-10부터. 새 계정·규정 위반 계정은 제외될 수 있음). 다만 스토리는 주로 팔로워에게 보이므로 릴스를 올릴 때 같은 시술 글로 가는 스토리를 함께 올리고, 시술별 하이라이트로 프로필에 남긴다. 하이라이트에서 스티커가 눌리는지는 앱에서 확인한다 (미확인). 스티커 링크도 추적 링크(`tracker add --target <글 주소> --label "IG story <시술>"`, `?s=ig`)로.
  - 1번(시술 글 → 여행 글 등 사이트 안 연결)은 홈페이지 세션이 사이트 전체를 검토하며 다룬다.
- **운영:** 숏폼 전용 세션에서 따로 한다. 워커·텔레그램·주간 리포트와 묶지 않는다 (붙이더라도 별도 작업으로).
- **받아쓰기:** 로컬 Whisper(`faster-whisper`). 시술·제품 이름 목록을 힌트로 넣고, 화면 글자(Claude)와 대조한다.
- **링크:** 스폰서 글과 광고 카드가 붙은 글로는 바로 연결하지 않는다. 릴스 유입은 병원별 영업 자료로 쓰지 않는다.
- **편집·게시:** 앱 조작 자동화(폰·브라우저 제어, Aside류)는 만들지 않는다. Meta 약관의 자동 접근 금지와 이 세션 규칙 때문이다. 앱에서 리믹스하고 임시저장·게시하는 것은 사람이 한다.

**흐름**
1. 운영자가 앱에서 원본 후보를 고른다. 자동 수집은 하지 않는다 (Meta 약관상 무단 수집 금지). 후보 목록은 공식 API 해시태그 검색(`reels find`).
2. 고른 영상만 번역 작업용으로 받는다 (2026-11-10 운영자 결정): 해시태그 결과의 `media_url`(공식 API, Instagram CDN)로 받고, Instagram 이 주소를 주지 않는 영상(약 절반, 음원 저작권 등 — 목록에 📼)은 운영자가 화면을 녹화해 `--file` 로 넣는다. 받은 영상·프레임은 게시하지 않고 작업 뒤 지운다.
   - 명령: `python -m pipeline.reels transcribe <번호>` / `--file 녹화.mp4 --permalink <릴스 주소>` (`--about Ultherapy` 로 끝 문구 시술 이름, `--keep` 영상 남김, `--force` 선별 검사 오탐 확인)
   - 결과: `content/reels/work/<id>/` — `subtitles.en.srt`, `caption.txt`(원작자 @ 는 운영자가 채움), `checklist.md`(판정·자막 원문 대조·화면 글자 위치·앱 확인 목록)
3. 시스템이 처리한다: 말소리 받아쓰기(로컬 Whisper, LLM 아님) → 화면 글자 인식(Claude, 프레임 이미지) → 코드 선별 검사 → Claude 번역 → Gemini 검수(원문 대조).
   - Claude 는 소리를 입력으로 받지 못해서 말소리는 로컬 받아쓰기를 쓴다. 대안은 Gemini 받아쓰기다.
4. 시스템이 결과물을 만든다: 구간별 영어 자막(시간 포함), 캡션(원작자 크레딧 + "개인 경험이며 결과는 다름"), 체크리스트.
   - 앱 시험에서 동시 재생이 확인되면 원본 길이에 맞춘 9:16 자막 영상(Remotion)도 만든다.
5. 운영자가 앱에서 리믹스해 게시한다. 리믹스는 API로 만들 수 없다.

**미확인:** 리믹스에서 갤러리 영상을 불러오면 원본과 동시에 재생되는지 (운영자 앱 시험 대기)

**해시태그 점검 (2026-11-10, `reels tags`, 인기·최근 24시간 각 1페이지).** 인기 게시물(top_media)은 거의 사진이거나 1년 넘은 영상이다. 영상은 최근 24시간(recent_media)에 몰리지만 대부분 병원 글이라, 캡션 검사를 통과하는 영상은 태그당 하루 0~3개다 (스킨부스터 3 · 피부시술 3 · 쥬베룩·울쎄라·써마지 1, 피부과브이로그·시술브이로그·시술후기·스킨부스터후기·리쥬란다운타임 0, 리쥬란vlog 는 해시태그 없음). 해시태그 결과에는 계정 이름이 없어 병원 계정의 안내형 영상("알려드립니다", "영상에서 확인해 보세요")이 통과하므로 ⚠️ 병원 안내 말투로 표시한다. 개인 크리에이터 원본은 해시태그보다 계정 단위로 찾는 편이 맞다 — 운영자가 앱에서 찾은 계정 이름으로 Business Discovery(공식 API, 비즈니스·크리에이터 계정만)를 쓰는 방식을 다음 작업 후보로 둔다.

**원본 선별 (코드 검사 + 사람 확인).** 아래에 해당하면 뺀다.
- 협찬 표시
- 표시 없는 협찬 신호: 병원 태그·멘션, 할인 코드, 예약 링크, "감사합니다 @병원", 같은 병원 반복 노출
- 캡션·말·화면 글자 속 대가 문구: 협찬, 광고, 체험단, 제품·시술 제공, 소정의 원고료, 경제적 이해관계 (유료 파트너십 표시가 없어도 뺀다)
- 병원 이름·간판·위치
- 시술 장면(주사·바늘), 전후 비교
- 원작자 외 다른 사람의 얼굴
- 리믹스를 꺼 둔 영상

번역은 원문 그대로 하고, 효과·추천을 더하지 않는다. 계정은 병원 돈과 엮지 않는다. 병원 광고는 별도 형식(병원이 광고주로 표시되고, 경험담 없이, 필요하면 심의)으로만 한다. 의료법 §56① 때문에 법인 등록으로 의료광고 주체가 될 수는 없다. 계정이 커지기 전, 병원과 엮이기 전에 의료광고 전문 변호사에게 확인한다.

### 계정·API 준비 (운영자, 2026-11-05 시작)

1. Skinbound 인스타그램(Threads와 연결된 계정)을 **비즈니스** 프로페셔널 계정으로 전환 (무료)
2. Facebook 페이지 "Skinbound" 생성 → 인스타그램 계정과 연결
3. Meta 개발자 앱: 인스타그램(Facebook 로그인 방식) 사용 사례 추가 — Threads 앱에 추가가 안 되면 새 앱
4. Graph API 탐색기로 개발 모드 시험: `me/accounts?fields=instagram_business_account` → `ig_hashtag_search?user_id=<IG id>&q=리쥬란` → `<hashtag id>/top_media?user_id=<IG id>&fields=id,caption,media_type,permalink,like_count,comments_count,timestamp`
5. 4번이 되면 앱 심사 없이 진행한다 (우리 계정만 쓰는 내부 용도). 장기 토큰과 IG 계정 ID 를 `.env` 에만 넣는다 (`INSTAGRAM_ACCESS_TOKEN`, `INSTAGRAM_USER_ID`)
6. 4번이 권한 오류면 앱 심사: 비즈니스 인증, 개인정보처리방침에 인스타그램 데이터 사용 추가, 사용 화면 녹화, 용도 설명

권한: `instagram_basic`, `pages_show_list`, `pages_read_engagement`, 해시태그 검색(Instagram Public Content Access), KPI용 `instagram_manage_insights`.

### KPI (초안 — 4주 뒤 조정)

출처는 숏폼 대행사 대표의 스레드 글(2026-11-04)이다. 근거 데이터가 공개되지 않았고 국내 계정 기준이라 시작값으로만 쓴다. 리믹스는 원본성이 낮아 추천이 덜 될 수 있으므로, 초기 조회수가 낮다고 바로 실패로 보지 않는다.

**1순위 지표 (2026-11-10): 인스타그램 → 홈페이지 도착 수.** 릴스는 홈페이지 유입 수단이므로 아래 비율들은 진단용이다. `python -m pipeline.reels traffic [--days 7] [--views <기간 조회 합계>]` — 프로필 추적 링크 누름(추적기), 인스타그램에서 온 추적 링크 클릭 전체, `/ig/` 페이지 요청(서버 기록, 봇 일부 포함 상한), 조회 1,000회당 도착. 조회수는 지표 API 연결 전까지 앱 인사이트에서 읽어 넣는다. 4주 시험의 중단 기준은 "4주 합계 도착 20 미만 또는 편당 평균 조회 500 미만"을 시작값으로 한다.

| 단계 | 지표 | 기준 | 미달 시 진단 |
|---|---|---|---|
| 도착 (1순위) | 홈페이지 도착 ÷ 조회 1,000회 | 첫 2주 평균을 기준선으로 | 링크 문구·도착 페이지·스토리 연결 |
| 노출 | 영상 조회수 | 500 미만이 이어지면 앱의 **계정 상태(추천 가능 여부)**를 먼저 확인한다. 새 계정으로 우회하지 않는다 | 계정 제한 또는 기본 문법 문제 |
| 시청 | 평균 시청 비율 (평균 시청 시간 ÷ 영상 길이) | 첫 2주 평균을 기준선으로 잡는다. 정의가 확정되기 전에는 대행사의 30%·40% 기준을 쓰지 않는다 | 낮으면 포장(리믹스 배치·자막 디자인), 중간이면 내용(원본 선택·첫 문장) |
| 팔로우 | 팔로우 ÷ 조회수 (조회 5만 이상 영상) | 0.1% 이상 정상 · 0.3~0.5% 우수 · 0.5% 이상 매우 좋음 | 0.1% 미만이면 기획부터 다시 |
| 프로필 | 프로필 방문 ÷ 조회수 (월간) | 1% 이상 | 소비만 되고 계정에 관심이 없음 |
| 링크 | 링크 누름 ÷ 프로필 방문 | 1% 이상 | 타깃이 안 맞거나 링크 문구가 약함 |

### 지표 API 관리 (할 일)

## 시장 조사 요약 (2026-11-03)

- **검색:** 미국 소비자의 49%, Z세대의 65%가 TikTok을 검색에 쓴다. 그러나 Google보다 TikTok을 선호하는 Z세대는 4%뿐이다.
- **AI 인용:** Google AI Overviews에서 가장 많이 인용되는 도메인은 유튜브(29.5%)다. 그중 94%가 긴 영상이고 쇼츠는 5.7%다.
- **K-뷰티 첫 접점:** SNS가 첫 접점이며, 후기(39.1%)와 인플루언서(38.5%) 비중이 크다.
- **TikTok:** 위험 안내가 없는 미용 시술 콘텐츠는 18세 이상 제한·추천 제외 대상이다. Branded Content Policy는 미용 클리닉·시술 홍보를 금지한다.
- **권고:** 재개한다면 유튜브를 먼저 하고(긴 영상도 검토), 인스타그램을 두 번째, 틱톡을 마지막에 한다.
- **스팸 위험:** 같은 틀의 영상을 대량으로 올리면 유튜브의 "대량 생산·반복 콘텐츠"(2026-07) 판정에 가까워진다. 적게, 내용을 다르게 만든다.
- **인플루언서가 되어야 하나:** 아니다. 시술 체험 영상은 의료광고 규정상 치료 경험담 위험이 있다. 우리 역할은 크리에이터와 AI가 인용하는 **검증된 참고 자료**다. 병목은 배포이므로, 크리에이터 협업이 숏폼 자체 운영보다 먼저일 수 있다.

## 로컬 세션 vs 클라우드 세션 (2026-11-04 검토)

**운영자 결정 (2026-11-04): 우선 클라우드 세션에서 코드만 짠다.** Reddit 세션처럼 브랜치에서 작업하고 PR로 올린다. 실제 글로 렌더링하거나 실험하는 단계는 나중에 이 PC에서 따로 한다.

클라우드 세션에서 지킬 것:
- `content/`·`.env`·`config/sponsors.yaml`이 없다. 실제 데이터 대신 테스트의 가짜 LLM(`llm.set_backend()`)과 임시 폴더(`SKIN_CONTENT_DIR`/`SKIN_LOG_DIR`)로 검증한다.
- 키를 클라우드 환경에 넣지 않는다. 실제 API 호출(Gemini TTS, Pixabay, 각 채널 API)은 로컬 검증 단계로 미룬다.
- 테스트: `pip install -r requirements.txt` 후 `python -m pytest -q`. ffmpeg나 Remotion이 필요한 테스트가 환경 때문에 실패하면 코드 문제와 구분해서 PR에 적는다.
- PR 설명에 "로컬에서 확인할 것"(실제 렌더링, API 연결, 필요한 키·설정)을 항목으로 남긴다.

아래는 로컬과 클라우드를 비교한 내용이다. 렌더링과 실험 단계에서 다시 참고한다.

| 필요한 것 | 위치 | 클라우드 세션 |
|---|---|---|
| 승인된 글·사실 목록 (대본의 원료) | `content/` (git 제외) | ❌ 없음 |
| 실험 기록·Flow 클립·렌더 결과 | `content/experiments/` | ❌ 없음 |
| Gemini TTS·검수 키, Pixabay 키 | `.env` (git 제외) | ❌ 없음. 클라우드에 키를 올려야 함 (키는 이 PC 밖에 두지 않는 원칙) |
| 스폰서 제외 판단 | `config/sponsors.yaml` (git 제외) | ❌ 없음 |
| Remotion | `video/node_modules` (git 제외) | △ 매번 `npm install` |
| ffmpeg (libass) | 이 PC에 설치됨 | △ 환경에 따라 다름 |
| 워커·텔레그램 (Hermes) | 이 PC | ❌ 연결 안 됨 |
| 완성 영상 확인·점수 매기기 | 이 PC의 파일 | ❌ 결과물이 PC로 오지 않음 |

**클라우드 세션이 맞는 경우:** 코드만 고치는 작업이다. 예를 들어 대본 규칙 검사, 게시 키트 문구, API 연동 코드가 그렇다. 테스트는 가짜 LLM과 임시 폴더를 써서 클라우드에서도 돈다. Reddit 세션이 이 방식으로 PR(#25~27)을 올렸다. 다만 실제 글로 시험 렌더링하는 단계는 결국 로컬에서 해야 한다.

**로컬 세션을 쓰는 조건:**
- 이 PC가 켜져 있어야 한다. 이미 Hermes 워커 때문에 필요한 조건이다.
- Reddit 세션과 같은 `main`을 쓰므로 커밋 전에 pull 한다 (아래 메모).
- 렌더링은 CPU를 쓴다. 워커가 작업하는 시간(목 09:00 주제, 매일 9시·20시 SNS)은 피한다.
