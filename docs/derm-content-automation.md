# 한국 피부과 시술정보 콘텐츠 자동화 프로젝트

> 목적: 외국인(영어권 우선)을 대상으로 한국 피부과 **시술 정보** 콘텐츠를 AI로 반자동 제작·배포해 채널 자산(구독자·검색 유입)을 쌓는다.
> 현 단계는 **순수 정보 콘텐츠**만 다룬다 (병원 광고 직접 진행 X). 병원 광고가 필요해지면 **광고 대행**(병원이 광고 주체) 구조로 하고, 환자 유치·여행 패키지는 유치사업자·여행업 등록 이후(3단계)에 한다.

---

## 0. 시스템 구성 요약

| 역할 | 도구 | 비고 |
|---|---|---|
| 파이프라인 개발 | **Claude Code** (Pro 플랜) | 스크립트·프롬프트·설정 작성 및 수정 |
| 운영(스케줄·실행) | **Hermes Agent** | 크론 작업, 스크립트 실행, 메신저 전달 |
| 찾기 (LLM) | **Gemini API** (유료 등급) | 주제 조사·트렌드 스캔·**출처 페이지 찾기** (Google 검색 연동) |
| 쓰기 (LLM) | **Claude Code CLI** (`claude -p`, Pro 로그인 — API 키 없음) | 코드가 받아 둔 출처 페이지 본문만 보고 사실 목록·숏폼 대본·블로그 작성 (2026-10-06 결정) |
| 자동 검수 | **다른 회사 모델** (Gemini API) + 규칙 코드 | 작성 모델(Claude)과 다른 회사 모델로 출처 대조·교차 검수 (6-0 참고) |
| 사람 검수 | **Telegram** (Hermes 메신저 게이트웨이) | 자동 검수 결과 기반 승인·수정, 영상 게시 전 확인 |
| TTS | 미정 (ElevenLabs / Google Cloud TTS 등) | 채널 전체 동일 목소리 고정 |
| 예약 게시 | 미정 (Buffer / Later / Metricool 등) | 공식 연동 지원 도구만 사용 |

**원칙**
- 운영 스케줄·실행은 Hermes 가 하고, Claude Code 는 Hermes 워커가 부르는 **작성 단계(`claude -p`)**에만 쓴다. Claude Code 대화 세션이 켜져 있을 필요는 없다 (CLI 로그인만 유지).
  - 역할 변경 (2026-10-06): 처음에는 Gemini 가 쓰고 Claude Code 가 검수했으나, Gemini 가 출처 페이지에 없는 내용을 사실로 적는 문제가 실제 운영에서 반복돼 **Gemini = 찾기·검수, Claude = 읽고 쓰기**로 바꿨다. 같은 회사 모델이 쓰고 검수하지 않는 원칙(6-0)은 유지.
  - Claude 사용량 한도(Pro)에 걸리면 그 요청은 버리지 않고 다음 워커 실행 때 다시 시도한다.
- 결정적(deterministic) 작업(렌더링·게시·파일 이동)은 Hermes 크론의 **no-agent 모드**(스크립트만 실행, LLM 미사용)로 돌린다.
- LLM 호출은 모델 교체가 쉽도록 한 곳에 모은다 (`pipeline/llm.py`). 필요 시 LiteLLM 등으로 추상화.
- 로컬 모델(qwen 등)은 사용하지 않는다. 추후 AI 상담 단계에서 개인정보를 다룰 때 재검토.

## 1. 사업 전제

| 항목 | 내용 |
|---|---|
| 단계 | 1단계: 정보 콘텐츠 채널 + 광고 대행 → 2단계: AI 상담 연결 → 3단계: 유치업 + 여행업 **풀 패키지** (시술·병원 혜택·숙박·교통·통역) |
| 타깃 | 영어권(미국·캐나다) + 동남아(태국·싱가포르). 대만은 2~3개월 후 소액 테스트 |
| 자원 | 병원 인맥 있음 / 해외 네트워크·외국어 인력 없음 → AI(LLM + TTS)로 대체 |
| 차별점 | 빠른 업데이트, 출처 기반 정확한 정보, 가격·다운타임 등 실용 정보, 시술 일정을 고려한 여행 정보 |

## 2. 채널 & 게시 빈도

| 채널 | 역할 | 빈도 |
|---|---|---|
| TikTok | 신규 발견·반응 테스트 | 주 5회 |
| Instagram Reels | 방한 전 탐색, 향후 DM 상담 창구 | 주 5회 |
| YouTube Shorts | 검색 연계, 긴 수명 | 주 5회 |
| 블로그/웹사이트 | 구글 검색 유입 자산 | 주 5편 |

- 영상 1편 → 3채널 **각각 네이티브 업로드** (워터마크 금지, 비율·도입부 채널별 조정) — 그래서 빈도는 채널마다 같고, 초안 1편 = 대본 + 블로그라 블로그도 같은 수 (2026-10-06)
- **주제 구성 (2026-10-06)**: 주 6개 후보(5편 + 예비 1) = 시술 정보 4 (시술·가격·이용 가이드·트렌드·후기·화장품) + 시술 × 여행 2. `config/channels.yaml` `topic_quota`, 유형 안에서는 수요 점수 순. 숏폼은 초기 영상으로 계정 주제가 분류돼 그 주제에 반응하는 시청자에게 퍼지므로, 시술 정보를 볼 사람을 모으려고 시술 계열에 집중한다 — 관광지만 다루는 글(`travel_guide`)은 하지 않는다.
- TikTok 제한: 스폰서(병원 광고) 콘텐츠 게시 불가 (Branded Content Policy, `channels.yaml` `sponsored_policy` — `06_publish` 가 막음), 트렌드 사운드 사용 금지(라이선스). 중립 정보 콘텐츠는 게시 가능
- 판단 시점: 4~6주 / 영상 20~30개 이후
- 보류 채널: 샤오홍슈, 페이스북, 라인

## 3. 콘텐츠 축

1. **시술 설명**: 리쥬란, 스킨부스터, 울쎄라, 슈링크, 레이저 토닝, 보톡스 등
   - 원리 / 적합 대상 / 통증 / 다운타임 / 권장 횟수 / 주의사항
2. **가격 가이드**: 한국 vs 미국·동남아 가격대 비교 (특정 병원 가격표 X)
3. **이용 가이드**: 예약 방법, 여행 일정 중 시술 순서, 부가세 환급 현황 등
4. **트렌드**: 외국인이 많이 받는 시술, 시즌별 추천
5. **후기 큐레이션**: 시술별 공개 후기 링크 + 자체 요약 (병원별 X)
6. **시술 × 여행** (정보만, 상품 판매·제휴 링크 X — 3단계 패키지의 수요 검증용)
   - 다운타임 기반 일정 ("도착 첫날 시술, 마지막 날은 피하기")
   - 시술 후 주의사항 × 여행 활동: 비행, 자외선, 사우나·찜질방, 음주, 수영 (의학적 주장은 출처 필수)
   - 시즌별 추천, 입국 요건(K-ETA 등 — 매번 검증), 교통·eSIM 등 실용 정보
   - 일정에는 시술 다음 날을 같은 도시의 가벼운 "경과 관찰일"로 둔다 (비행·장거리 이동·사우나·음주·강한 햇빛 X, 재방문 필요 여부 병원 확인) — `_rules.md` 반영 (2026-09-28)
   - 병원이 특정되는 지역 안내 금지 ("○○의원 근처 호텔" X, "압구정역 일대" O)
   - 02b: 날짜별 일정(Day 1, Day 2 …)이 있는데 관찰일(observation day)이 없으면 ⛔ (2026-09-29)

8. ~~**관광지 소개·코스** (2026-09-29 추가, 축 `travel_guide`)~~ → **2026-10-06 제외**: 관광지만 다루는 글은 시술 정보를 볼 사람이 아니라 관광객을 모아 숏폼 계정 주제를 흐린다. 관광지 데이터·트렌드·코스 규칙은 **시술 × 여행(6번)** 글 안에서만 쓴다 (트렌드 장소·맛집은 주제 후보로 직접 올리지 않고 수요 정보로만). 아래는 그때 만든 데이터·규칙 기록

## 4. 자동화 파이프라인

```
[1 주제선정] → [2 초안생성] → [2.5 자동검수] → [3 텔레그램 검수] → [4 영상제작] → [5 게시 전 확인] → [6 예약게시] → [7 리포트]
  Hermes+Gemini  Gemini 찾기      규칙+출처+교차모델   사람(걸린 것 위주)  Hermes 스크립트   사람(Telegram)     Hermes 스크립트  Hermes+Gemini
                 →Claude 쓰기     (Gemini)
```

| 단계 | 실행 주체 | 모드 | 내용 |
|---|---|---|---|
| 1. 주제 선정 | Hermes 크론 (월 09:00) | 에이전트 + Gemini | 검색 키워드·트렌드·경쟁 채널 인기 영상 조사 → 주간 주제 5~7개 텔레그램 전송 → 사람이 선택 |

> 초기 운영: `config/seed_topics.yaml`(2026-09-28 조사, 25개, wave 1~3) 에서 주 6개씩 먼저 제안 → 소진 후 Gemini 주제 조사로 자동 전환.
| 2. 초안 생성 | Hermes 워커 (주제 선택 직후) | 스크립트 + Gemini + Claude | ① Gemini 가 검색으로 읽을 페이지 후보만 고름 → ② 코드가 페이지를 받아 404·빈 페이지·병원 사이트 제외 → ③ Claude 가 그 본문만 보고 사실 목록(사실마다 **원문 인용**)·숏폼 대본(30~60초)·블로그(1,200~2,000단어) 작성 (쓸 만한 페이지가 5개 미만이면 Claude 가 추가 검색) → ④ 코드가 인용문이 페이지에 실제로 있는지 대조, 없으면 그 사실 제외 |
| 2.5 자동 검수 | Hermes (초안 생성 직후) | 스크립트 + 검수 모델 | 규칙 검사 → 출처 검증 → 교차 모델 검수 → 통과/주의/차단 등급 부여 (6-0 참고) |
| 3. 초안 검수 | 사람 | Telegram | 자동 검수 등급 기반 승인 / 수정 요청 / 폐기 (6장 참고) |
| 4. 영상 제작 | Hermes 크론 | no-agent (스크립트) | `approved/` 대본만 대상. TTS + 자막 + B롤 합성 |
| 5. 게시 전 확인 | 사람 | Telegram | 렌더링 영상 미리보기 확인 → "게시 OK" |
| 6. 예약 게시 | Hermes 크론 | no-agent (스크립트) | `ready_to_publish/`만 대상. 채널별 업로드, AI 생성 라벨 ON |
| 7. 주간 리포트 | Hermes 크론 (일 20:00) | 에이전트 + Gemini | 채널별 조회·완주율·공유·팔로우·프로필 방문 요약 → 텔레그램 전송 |

### 영상 제작 원칙 (TTS/AI 생성)
- 채널 전체 **동일 TTS 목소리** 고정 (브랜드화)
- 첫 2~3초: 질문형 훅 + 움직이는 화면 (정적 슬라이드 지양)
- 큰 자막, 30~60초
- AI 인물/음성은 **설명자 역할만**. "제가 받아봤는데요" 식 체험담 금지
- 업로드 시 플랫폼 AI 생성 콘텐츠 라벨 활성화

## 6. 검수 흐름

### 6-0. 자동 검수 (3단계) — `02b_auto_review.py`

| 단계 | 방식 | 확인 항목 |
|---|---|---|
| ① 규칙 검사 | 코드 (LLM 없음) | `banned_terms.txt` 금지어, 병원명·의사명 패턴, 전화번호·예약 URL, "board-certified" 등 자격 표기 |
| ② 출처 검증 | 코드 + Gemini | 모든 출처 URL 접속 확인(HTTP 200), 페이지 본문에 해당 주장이 실제로 있는지 대조 (가짜·깨진 출처 차단). 병원 사이트로 보이는 출처는 ⚠️ |
| ③ 교차 모델 검수 | **작성 모델(Claude)과 다른 회사 모델 (Gemini)** | 7장 체크리스트 기준: 과장·단정 표현, 사실 오류, 체험담 형식, 비교 표현 |

> 작성 단계에서 이미 원문 인용 대조(코드)를 거치므로 ②는 두 번째 확인이다. 선택 기능: `config/models.yaml` 에서 검수 단계를 `claude_code` 로 바꾸면 02c 외부 검수 방식(요청 파일 + `claude -p`)으로 돌아간다 — 단, 작성도 Claude 이므로 같은 회사 원칙에 어긋나 쓰지 않는다.

**등급 기준**
| 등급 | 조건 | 처리 |
|---|---|---|
| ✅ 통과 | ①②③ 모두 문제 없음 | 사람 검수 생략 가능 (신뢰 단계에 따라 무작위 샘플만 확인) |
| ⚠️ 주의 | ③에서 경미한 지적, 또는 ② 일부 출처 약함 | 지적된 문장만 자동 수정 1회 → 재검수 → 사람 검수 필수 (2026-10-06) |
| ⛔ 차단 | ① 금지 항목 걸림, 또는 ② 출처 검증 실패 | 자동 재생성 1회 → 그래도 차단이면 사람 검수 |

> 구현 메모: 출처 사이트가 봇 접속을 막는 경우(401/403/429)와 PDF·본문 추출 불가 페이지는 ⚠️ 주의(사람이 직접 확인)로 처리한다. 404·연결 실패·본문과 불일치는 ⛔ 차단.

**항상 사람이 보는 항목 (등급과 무관)**
- 가격·수치가 포함된 콘텐츠
- 새로운 콘텐츠 유형의 첫 게시물
- 병원·의사가 언급된 모든 콘텐츠 (원칙적으로 ①에서 차단)

**신뢰 단계 (사람 검수 비중을 점진적으로 축소)**
| 기간 | 사람이 볼 것 | 다음 단계 조건 |
|---|---|---|
| 1~4주 | 전부. 자동 등급과 사람 판단 일치 여부를 `logs/review_agreement.csv`에 기록 | 일치율 충분히 높음 + 통과 건에서 놓친 위반 없음 |
| 5~8주 | 주의·차단 + 통과 건 20% 무작위 | 위와 동일 |
| 9주~ | 주의·차단 + 통과 건 10% 무작위 | 위반 발견 시 이전 단계로 복귀 |

- 원칙: 같은 모델이 쓰고 검수하지 않는다. 법적 책임은 운영자에게 있으므로 **완전 위임은 하지 않는다.**
- 예상 사람 검수 시간: 1~4주 주 1~2시간 → 이후 주 20~30분

## 11. Claude Code 작업 규칙 (CLAUDE.md에 포함)

- 개발은 Claude Code 대화 세션으로, 운영은 Hermes가 한다. 운영 중 Claude 는 워커가 부르는 작성 단계(`claude -p`)로만 쓴다. 스크립트는 사람 개입 없이 CLI로 단독 실행 가능해야 한다.
- 모든 LLM 호출(Claude CLI 포함)은 `pipeline/llm.py`를 통해서만 한다. 모델명은 `config/models.yaml`에서 읽는다.
- API 키·봇 토큰은 환경변수로만 읽고, 코드·로그·저장소에 남기지 않는다.
- 파일 상태 이동(drafts → approved → rendered → ready_to_publish → published)은 `03_review.py`와 정해진 스크립트만 수행한다.
- `06_publish.py`는 `ready_to_publish/` 외의 경로를 처리하지 않는다. 이 제약을 우회하는 코드를 만들지 않는다.
- 생성 프롬프트에는 7장 금지 사항과 "모든 사실에 출처 URL" 규칙을 반드시 포함한다.
- 각 스크립트는 실패 시 0이 아닌 종료 코드와 원인 로그를 남긴다 (Hermes 실패 알림용).

## 12. 사업 구조 및 법적 확인 사항

> 조문은 국가법령정보 Open API 수집본(`legal/digest.md`, 2026-09-27 조회) 기준. `law_sync.py`가 주 1회 변경을 감지한다. 본 장은 법률 자문이 아니다.
> 국민신문고 서면 질의는 **보류** (광고 대행 단계에서는 진행하지 않음, 3단계 착수 전 재검토).

### 12-0. 현재: 정보 콘텐츠 채널
- 출처 원칙 (2026-09-28 결정): 중립 글은 병원 사이트를 출처·링크로 쓰지 않는다 (특정 병원 무상 노출 = 광고·유인 소지, 스폰서 상품 가치 훼손, 병원 사이트는 광고물이라 근거로 약함). 신뢰는 공식 출처(논문·정부·학회·제조사 제품 페이지)와 **Medical Korea 외국인환자 유치의료기관 명단** 같은 공식 조회 링크로 확보. 병원 링크는 스폰서 글에만.
- 정보 채널은 병원·의사를 특정하지 않는 한 의료광고(의료법 §56①: "의료행위, 의료기관 및 의료인등에 대한 정보를 소비자에게 나타내거나 알리는 행위")로 보일 여지를 최소화한다. 병원명·예약 링크·병원별 가격 금지 원칙 유지
- **AI 생성물 표시 의무 (AI 기본법 §31, 시행 2026.1.22)**: 생성형 AI 결과물임을 표시(②), 실제와 구분하기 어려운 가상 음성·영상은 이용자가 **명확히 인식할 수 있게** 고지(③). TTS·AI 영상을 쓰는 우리는 "인공지능이용사업자"(§2 7호 나목)에 해당 → 플랫폼 AI 라벨 + 영상 내 표기 모두 적용

### 12-1. 광고 대행 (병원이 광고 주체) — 필요 시
- [ ] 광고 명의·주체는 병원. 의료인등이 아닌 자는 의료광고 불가 (의료법 §56①) → 대행사는 제작·집행만
- [ ] **사전심의 필수**: SNS 광고는 전년도 말 기준 직전 3개월 일평균 이용자 10만 명 이상 매체면 심의 대상 (§57①5호, 시행령 §24②) → Instagram·YouTube·TikTok 모두 해당. 심의 유효기간 3년 (§57⑧)
- [ ] 금지 광고 (§56②) 를 `banned_terms.txt`·자동 검수 규칙에 반영: 치료경험담(2호), 거짓(3호), 비교(4호), 시술 장면 노출(6호), 부작용 누락(7호), 과장(8호), 근거 없는 자격·명칭(9호), 기사·전문가 의견 형태(10호), **비급여 진료비 할인·면제의 기만적 광고(13호)**, 상장·인증·추천 표방(14호)
- [ ] 대행 수수료는 정액 광고비 구조. 환자 수·매출 연동은 영리 목적 알선(§27③) 위험

### 12-1-1. 스폰서 트랙 (광고 대행 운영 방식, 2026-09-27 결정)
- 구조: 광고주(병원)가 광고 주체, 우리는 **매체(게재) + 제작 대행**. 신문이 병원 광고 지면을 파는 것과 같은 구조로, 기사(중립 정보)처럼 위장하지 않는다.
- 대가: **정액만** (월 구독 또는 글당). 환자 수·예약·매출 연동 금지 (§27③). `sponsors.yaml` 은 계약 유형을 monthly/per_post/pilot 로만 받는다 (pilot = 무상 파일럿, 아래).
- 표시: 모든 스폰서 글에 "Sponsored content — this is an advertisement by <병원>" (블로그 상단), "Sponsored by <병원> · Advertisement · AI-generated content" (영상) 자동 삽입 (표시광고법 §3·추천보증 심사지침, AI 기본법 §31).
- 내용: 의료법 §56② 금지 광고 전부 차단 — 치료경험담, 타 병원 비교·최상급, 과장·보장, 전후 사진, 부작용 누락, 가격·할인·이벤트, 근거 없는 수상·인증. 광고주 병원명과 공식 사이트 링크만 허용, 다른 병원·의사명·연락처 금지. 의학적 사실은 병원 사이트가 아닌 독립 출처.
- 승인: 자동 검수(규칙·Gemini 교차 검수) → **병원 최종본 확인(`병원확인`)** → 사람 승인. 재생성되면 병원 확인 무효.
- 사전심의: 게재 매체가 심의 대상(§57①, 시행령 §24②)이 되면 `ad_review_required: true` + 심의번호 없이는 ⛔.
- 트랙 분리: 중립 정보 글에 스폰서 병원명·사이트가 나오면 ⛔ (대가 받은 병원의 숨은 노출 방지).
- AI 검색 관점의 세일즈 문구: "외국인 환자가 AI로 검색할 때 병원 공식 정보가 정확히 인용되도록 콘텐츠를 제작·배포" (광고 표시가 있어도 크롤링·인용됨). "AI가 우리 병원을 추천하게 만든다"는 표현은 쓰지 않는다.
- **플랫폼 정책 (2026-09 확인)**: 스폰서 콘텐츠는 **틱톡 게시 불가** (Branded Content Policy — 미용 클리닉·시술 홍보 금지). 인스타그램은 브랜디드 콘텐츠 도구(유료 파트너십 라벨) + 18세 이상 연령 제한, 유튜브는 "유료 프로모션 포함" 표시로만 가능. 블로그가 스폰서 트랙의 주 무대. SNS 프로필에는 스폰서 병원 링크를 걸지 않고 우리 블로그만 건다. 설정: `config/channels.yaml` sponsored_policy (06_publish 가 강제 예정).
- **영업 근거 데이터 3종 (2026-09-28)**: ① 중립 글의 "등록 병원 찾기(Medical Korea 공식 명단)" 안내 클릭 = 병원을 찾으러 나간 독자 수 (추적 링크, 개별 병원 노출 없이 구매 의사 증명) ② 블로그 방문·AI 검색 유입 (Cloudflare Web Analytics) ③ 인맥 병원 1~2곳 **무상 파일럿 스폰서**의 실제 병원 사이트 이동 수 (광고 표시·병원 확인 동일 적용). 중립 글에 병원 링크를 넣어 데이터를 만들지 않는다.
- 유입 증빙: 블로그 스폰서 글에 거는 병원 링크는 추적 링크(`tracker/`)로 발급해 채널·콘텐츠·국가별 클릭과 AI 검색 답변 경유 클릭을 기록하고, 병원 월간 리포트로 제공한다. UTM 을 붙여 병원 애널리틱스에서도 교차 확인 가능. 수치는 성과 보고용이며 과금은 정액 유지.
- **코스 주변 병원 목록 (2026-09-29 결정)**: 중립 여행 글(procedure_travel, travel_guide) 하단에 코스 관광지 반경(기본 700m) 안의 피부과 진료 의료기관을 **빠짐없이 거리순으로** 붙인다 (`pipeline/clinics.py`, 심평원 병원정보서비스 공공데이터).
  - 왜 알선이 아닌가: 판례상 §27③ 소개·알선은 환자와 **특정** 의료기관 사이 진료계약 성립을 중개하는 행위, 유인은 기망·유혹(금품·할인 등)으로 특정 기관과 계약하게 하는 행위이고, 광고는 원칙적으로 유인이 아니다. 공공데이터 기준으로 전부·거리순·대가 없이 나열하는 것은 지도 앱과 같은 정보 제공에 가깝다.
  - 선을 넘는 경우: ① 우리가 고르거나 "가장 적합한/추천" 표시 (선택 = 광고성, §56① 비의료인 의료광고 시비 + 스폰서가 섞이면 표시광고법 기만) ② 돈을 받고 목록 포함·제외·순서 조정 ③ 환자 수·예약 연동 대가 (§27③). 그래서 기준은 코드로 고정하고 모든 글에 같은 기준(`site.yaml` clinic_directory), 표시 항목은 이름(한글 등록명)·종별·동·거리·지도 검색 링크만, 스폰서는 같은 자리에 "Advertiser" 표시.
  - 향후 스폰서 상품: 목록과 분리된 **광고 표시 박스**(예: "Advertisement — 이 코스 근처 광고주 병원")나 스폰서 `--course` 글로만 판다. 거리순 목록 자체의 순서·포함 여부는 팔지 않는다.
  - [ ] 영업 전 변호사 확인 항목에 추가: 중립 글 하단 전수 목록 + 광고주 표시 방식의 §56①·표시광고법 적합성
- **코스 광고 카드 (2026-09-29 결정)**: 중립 여행 글 하단(병원 목록 뒤)에 같은 권역 광고주 1곳의 작은 카드. 월정액(또는 파일럿), 병원이 카드 문구 확인(`route_ad.confirmed`), 문구는 금지 표현 검사, "Ad · Sponsored" 표시와 "추천 아님" 문구는 항상 노출(표시광고법·추천보증 심사지침, 미국 FTC 가이드 모두 "명확하고 눈에 띄게"). 광고를 **작게·조용히** 두는 것은 괜찮지만 **광고 표시를 흐리게** 하는 것은 안 된다. **글 하나에 광고 하나(독점 지면)** — 한 글에 여러 광고를 섞지 않는다. 배정된 글은 계약 기간 동안 그 광고주 전용(새 광고주가 와도 안 바뀜), 같은 권역에 광고주가 여럿이면 새 글을 배정이 적은 쪽에 나눠 준다. 상위 상품으로 **권역 독점**(`route_ad.exclusive`) — 계약 기간 동안 그 권역 여행 글의 광고 카드는 한 병원만. 계약이 끝나면 다음 빌드에서 자동으로 빠지고 그 글은 다음 광고주에게 넘어간다. 클릭은 추적 링크로 도착 수에 잡힌다.
  - §56②12(외국인환자 유치 목적 국내광고 금지) 대응: 영어·해외 대상 광고로 운영하고, 한국 방문자에게는 카드를 숨긴다(`route_ads.hide_in_countries: [KR]`, 국가 확인 실패 시 숨김). 해외 대상 온라인 광고는 국내광고가 아니라는 해석이 일반적이지만 명문 규정이 없어 변호사 확인 항목 유지. 광고주는 외국인환자 유치의료기관 등록 병원을 권장.
- **병원 중심 코스 글 (2026-09-29)**: 스폰서(광고) 글 한정으로 병원 권역(`zone`, `area`) 기준 여행 코스를 붙일 수 있다 (`--course`) — 시술 당일·관찰일을 병원 근처 실내 장소로. 광고 표시·병원 확인 동일, 코스에 픽업·할인·패키지 등 혜택 금지(§27③). 중립 글·주제 추천에서 "코스에 가장 맞는 병원"을 추천·매칭하는 기능은 두지 않는다 (§27③ 알선, 표시 없는 병원 광고, 12-3 시스템의 선).
- **무상 파일럿 (2026-09-28)**: 인맥 병원 1~2곳에 `contract.type: pilot` 으로 무료 게재 (최대 183일, 이후 정액 전환 또는 종료). 대가가 없어도 병원 명의 광고이므로 광고 표시·병원 확인·트랙 분리·플랫폼 정책은 유료와 똑같이 적용. 표시 문구만 사실대로: "Partner content — this is an advertisement by <병원> (unpaid pilot partnership, no fee paid)" / 영상 "Partner content with <병원> · Advertisement (unpaid pilot)", 블로그 배지 "Partner · Ad". 파일럿 조건으로 할인·무료 시술·환자 소개를 주고받지 않는다.
- 계약서 초안: `docs/templates/pilot-agreement.md`(무상 파일럿), `docs/templates/ad-placement-terms.md`(유료 정액 약관) — 변호사 검토 후 사용
- [ ] 병원 영업 전 변호사 확인: 표시된 병원 명의 광고를 우리 채널이 정액으로 게재·제작 대행하는 구조의 §56① 적합성, 채널 규모별 사전심의 대상 여부

### 12-2. 3단계: 유치사업자 + 여행업 풀 패키지
등록한 외국인환자 유치사업자는 의료법 §27③ 유인·알선 금지의 예외(§27③2호: 건강보험 가입자·피부양자가 아닌 외국인, 국내 거주 외국인 제외)가 적용되어 시술·병원 혜택·숙박·교통을 패키지로 판매 가능. 보험회사·보험설계사 등은 불가(§27④).

| 요건 | 근거 | 내용 |
|---|---|---|
| 유치사업자 등록 | 의료해외진출법 §6②, 시행규칙 §4②③ | 보증보험 **1억 원 이상**, 자본금 **1억 원 이상**(법인은 납입자본금, 개인은 영업용 자산평가액), 국내 사무소. 시·도지사 등록 |
| 등록 유효기간 | §6⑥⑦ | **3년**, 만료 전 갱신 |
| 결격 | §6③ | 이 법 위반 실형 후 2년 미경과 등 |
| 제휴 병원 | §6① | **외국인환자 유치의료기관** 등록 필수 (진료과목별 전문의 1명 이상, 배상책임보험 의원급 연 1억 원 이상) |
| 수수료 | §9 | 복지부 **고시 수수료율** 초과 금지 (알려진 상한: 의원 30%·병원 20%·상급종합 15% — 고시 원문 추적 필요), 거짓 정보 제공 금지 |
| 등록증 대여 금지 | §7 | 명의 대여 불가 |
| 여행 부분 | 관광진흥법 §4 | 숙박·교통 포함 상품 판매 시 여행업 등록 또는 등록 여행사 제휴 (자본금 등 등록기준은 시행령 별표 — 별표 API로 추후 확인) |
| 대상 확인 | 의료법 §27③2호 | 국내 비거주 외국인만 → 예약·상담 단계 거주지 확인 절차 |

**⚠️ 핵심 리스크: 패키지 홍보 광고** (조문 확인 결과 기존 우려가 구체화됨)
1. 유치사업자는 "의료인등"이 아니므로 **스스로 의료광고를 할 수 없다** (의료법 §56①). 병원명·시술·가격이 들어간 패키지 홍보는 의료광고에 해당할 가능성이 높다.
2. 의료인등도 **외국인환자 유치를 위한 국내광고는 금지** (§56②12호). 예외는 유치의료기관이 공항·면세점·무역항·지정 관광특구 등에서 하는 외국어 광고뿐이며(의료해외진출법 §15①), 이 경우도 사전심의 필수(§15②), 전후 비교 사진 금지(§15① 단서), **공항·항만에서는 피부과·성형외과 편중 광고 금지**(§15③).
3. 따라서 현실적 구조는 **광고 주체 = 유치의료기관(병원), 대상 = 해외(국외 광고), 사전심의 통과, 유치사업자는 대행·패키지 운영**. 해외 타깃 SNS 광고가 "국내광고"에 해당하지 않는지가 남는 쟁점 → 3단계 착수 전 전문 변호사 확인
4. 수익 구조는 병원 수수료(고시 상한 내) + 여행 상품 마진으로 분리, 패키지 내 진료비는 분리 정산

### 12-3. 시스템의 선: "병원 사이트 도착"까지 (2026-09-28 결정)
이 시스템(정보 채널 + 스폰서 트랙)이 하는 일은 **외국인 독자를 병원 공식 사이트까지 보내는 것**, 즉 마케팅 영역에서 끝난다.

| 단계 | 지표 | 측정 | 범위 |
|---|---|---|---|
| 관심 | 블로그 방문, AI 검색 유입 | Cloudflare Web Analytics | 우리 |
| 의도 | 중립 글 → 등록기관 목록(Medical Korea) 클릭 — **글·시술별** | 추적 링크 `_registry:<글>` | 우리 |
| 도착 | 스폰서·파일럿 글 → 병원 공식 사이트 클릭 (UTM) | 추적 링크 + 병원 GA4 교차 확인 | 우리 |
| 전환 | 상담·예약·결제·내원 | 병원 자체 | **범위 밖** |

- 전환(실제 구매)으로 가는 상담 연결·예약 대행·환자 알선은 하지 않는다. 그 단계는 외국인환자 유치사업자 등록(12-2) 후 별도 사업으로 한다. 예약·전환 수치를 받아 과금하거나 리포트에 넣지 않는다.
- 분석(`python -m pipeline.analytics report --month YYYY-MM`, 매월 1일 크론): 추적기 집계(`/api/export`, 방문자 해시 제외) + 글 메타데이터 + 시술 분류(`config/procedures.yaml`) → `reports/analytics/<기간>.md|.csv` (git 제외). 표: 시술별 관심도(의도·도착), 글별, 채널(AI 검색 포함), 국가, 주별 추이, **영업 벤치마크**(글 1개당 평균 의도 클릭 / 스폰서·파일럿 글 1개당 평균 도착).
- 데이터셋 활용 원칙: 다른 병원 제안서에는 집계(시술별·국가별·글당 평균)만 쓰고 파일럿 병원명·병원별 수치는 그 병원 동의 없이 공개하지 않는다. 개인 단위 데이터는 애초에 수집하지 않는다(IP 미저장, 하루 단위 해시).
