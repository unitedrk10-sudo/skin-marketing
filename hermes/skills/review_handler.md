# 텔레그램 검수 답장 처리 스킬

역할: 사람의 텔레그램 답장을 `pipeline/03_review.py apply` 가 이해하는 **정규 형식**으로 바꿔 실행하고, 결과를 그대로 답장한다.
파일을 직접 옮기거나 수정하지 않는다. 상태 이동은 `03_review.py` 만 한다.

## 정규 형식 (한 줄에 명령 하나)
| 의미 | 형식 |
|---|---|
| 승인 | `1,3,4 승인` (범위 `1~3 승인`) |
| 전체 승인 | `전체 승인` |
| 수정 요청 | `2 수정: <요청 내용 원문 그대로>` |
| 폐기 | `5 폐기` |
| 게시 확인 (`--stage rendered`) | `게시 OK` 또는 `1,2 게시 OK` |

## 해석 규칙
- 번호는 가장 최근 검수 요청 메시지의 번호다. 답장에 번호가 없고 대상이 모호하면 **실행하지 말고 되묻는다**.
- "좋아요", "다 괜찮아" 처럼 명확한 전체 승인 의사 → `전체 승인`. 애매하면 되묻는다.
- 수정 요청 내용은 요약하지 말고 사람이 쓴 문장을 그대로 넘긴다.
- 사람이 "⚠️ 건도 승인", "경고 무시하고 전부" 라고 명시한 경우에만 `--confirm` 을 붙인다.
- 게시 확인 단계(렌더링 영상 메시지에 대한 답장)면 `--stage rendered` 를 붙인다.

## 실행 결과 처리
- 종료 코드 0: stdout 을 그대로 답장. 수정 요청이 포함됐으면 이어서 `python -m pipeline.03_review list` 로 새 검수 요청을 보낸다.
- 종료 코드 2: stdout 의 `❓` 메시지를 보여주고 다시 답장을 요청한다.
- 종료 코드 1: 실패 알림 (로그: `logs/03_review.log`).

## 금지
- `06_publish.py` 실행, `content/` 파일 직접 이동·삭제, 검수 등급 무시한 승인 권유.
